# Usage Reference

This skill can run outside the Codex runtime while still reusing local Codex configuration when present. It reads `$CODEX_HOME/config.toml` or `~/.codex/config.toml`, then `$CODEX_HOME/auth.json` or `~/.codex/auth.json`.

Connection precedence:

1. Explicit `--base-url` and `--api-key` CLI values.
2. Codex config/auth files.
3. `OPENAI_BASE_URL` / `OPENAI_API_BASE` and `OPENAI_API_KEY`.
4. Interactive prompts.

## Minimal Example

```bash
python scripts/stream_responses_image.py \
  --model "gpt-5.5" \
  --image-model "gpt-image-2" \
  --prompt "Generate a square warm editorial illustration of a cozy desk scene with a mug and notebook. No text, no logo, no watermark." \
  --out output/imagegen/desk.png
```

If Codex config/auth are available, no base URL or key prompt is needed.

## Explicit Gateway Override

```bash
export OPENAI_API_KEY="sk-..."
python scripts/stream_responses_image.py \
  --base-url "https://codex.miyuzu.top/v1" \
  --prompt "Generate a square warm editorial illustration of a cozy desk scene with a mug and notebook. No text, no logo, no watermark." \
  --out output/imagegen/desk.png
```

## Interactive Key Prompt

If Codex auth and `OPENAI_API_KEY` are unavailable, the script asks for the key with a hidden terminal prompt:

```bash
python scripts/stream_responses_image.py \
  --base-url "https://codex.miyuzu.top/v1" \
  --prompt-file prompt.txt \
  --out output/imagegen/result.png
```

## Prompt File

Use `--prompt-file` for long prompts:

```bash
python scripts/stream_responses_image.py \
  --prompt-file prompt.txt \
  --out output/imagegen/mondstadt.png
```

## Optional Request JSON

Use `--save-request-json` to inspect the request without exposing the key:

```bash
python scripts/stream_responses_image.py \
  --prompt-file prompt.txt \
  --out output/imagegen/result.png \
  --save-request-json tmp/request.json
```

The saved JSON contains the model, prompt, stream flag, and tool definition. It does not contain the API key.

## Defaults

- Outer model: `gpt-5.5`
- Image tool model: `gpt-image-2`
- Endpoint: `POST {base_url}/responses`
- Streaming: always enabled
- Output format: inferred from `--out`; generated bytes are written exactly as returned
- Timeout: `420` seconds

## Known Gateway Behavior

In one tested gateway, `/images/generations` returned:

```text
503 no_available_providers
```

The streamed Responses path succeeded with:

```json
{
  "model": "gpt-5.5",
  "stream": true,
  "tools": [
    { "type": "image_generation", "model": "gpt-image-2" }
  ]
}
```

The image was delivered through `response.output_item.done` as:

```json
{
  "item": {
    "type": "image_generation_call",
    "result": "<base64 image>"
  }
}
```

## Troubleshooting

If no image is saved, check the event summary printed by the script.

Common cases:

- `response.created` but no `image_generation_call`: try outer model `gpt-5.5`.
- HTTP 401 or 403: the API key is wrong or unauthorized.
- HTTP 404: the gateway may not support `/responses` at that base URL.
- Long wait with keepalive events: generation is still running; increase `--timeout`.
- `No image_generation_call result found in stream`: the model completed without using the image tool.

## Security

Do not commit API keys. Prefer `OPENAI_API_KEY` or the hidden prompt. Avoid shell history exposure by not passing `--api-key` on shared machines.
